# 2.x 改进计划

本文记录 v2.0 基线之后的工程改进方向。目标不是继续堆叠功能，而是把项目收敛为一个可恢复、可审计、可离线评测的本地优先 Agent Runtime。

## 当前基线

- Python 测试：132 项通过，总覆盖率 46.25%。
- Web：React 18、Vite、Tailwind CSS，具备聊天、模型与思考强度选择、工具审批、会话管理和用量展示。
- 运行时：具备工具循环、持久化、恢复账本、RAG、多智能体、审计与离线评测。
- 发布状态：v2.0.0 已进入远端 `main`；本地 wheel 隔离安装、冻结依赖和一键发布门禁已验证，GitHub Release 与远端仓库保护仍需管理员操作。

## v2.0.1 — 发布可信度与界面基础

- [x] 修复 wheel 中缺失 `app.py`、`cli.py` 导致安装后命令不可用的问题。
- [x] 提交 `uv.lock`，CI 使用冻结依赖安装。
- [x] 清理未使用的 Web 依赖并关闭现有高危依赖告警。

- [x] 改进应用壳层、移动端导航、聊天工具栏和输入区的响应式交互。

验收：Python 测试、Web 构建、npm audit、wheel 安装、CLI 启动和浏览器核心页面检查全部通过。

## v2.1 — 质量门禁与仓库治理

- [x] 前端增加 ESLint、Vitest、React Testing Library 和 axe 可访问性检查，并接入 CI。
- [x] Playwright 覆盖无密钥可验证的任务建议、输入焦点、主题保存和移动端导航。
- [x] Playwright 使用隔离的内存 HTTP/SSE 替身覆盖新建会话、发送与删除；Vitest 覆盖中断后重发且不重复用户消息。
- [x] Playwright 使用可控挂起工具调用夹具覆盖审批允许、拒绝和超时，并验证非流式活动会话仍能恢复待审批卡片。
- [x] CI 执行完整 Ruff；Mypy 已对完整 `core/` 与 `shared/` 启用阻断门禁，其余模块继续分批收敛。
- [x] 为 Agent 主循环、工具分发、执行账本和会话存储设置独立覆盖率下限，并在 CI 与本地发布证据中阻断回归。
- [ ] 启用 main 分支保护、Secret Scanning、Push Protection 和 Dependabot 自动安全更新（远端仓库管理员操作；本地核验清单已补齐）。
- [x] 固定 GitHub Actions 到提交 SHA，并为 npm、Python、Actions 配置 Dependabot。

验收：受保护分支必须通过 Python、Web、浏览器、CodeQL 和依赖审查门禁后才能合并。

当前质量基线：全量 Ruff 已清零并进入阻断门禁；`core/` 与 `shared/` Mypy 已清零并保持阻断。无调用方的 `services/` 浅层已删除，剩余插件类型债务以非阻断 CI 作业持续公开，按运行时边界分批收敛。

关键模块门禁基线来自当前真实覆盖率并保留小幅演进余量：Agent 主循环 85%、工具分发 80%、执行账本 70%、会话存储 80%。检查器同时接受 Windows 与 Linux 路径格式；目标模块缺失时直接失败，避免重命名或采集遗漏绕过门禁。

## 暂不推进

- 没有真实部署需求时不引入 Kubernetes 或微服务拆分。
- 核心链路未完成测试前不继续增加大量适配器。
- 未完成租户隔离、限流、密钥管理和长期负载验证前，不宣称生产就绪。
