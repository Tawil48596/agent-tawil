# v1.4–v2.0 工程路线

目标是把项目从功能型本地 Agent 平台推进为“可靠、可评测、可审计、可迁移”的本地优先 Agent Runtime。每个版本必须有代码、自动化测试和可复现命令，不把规划能力写成已完成功能。

当前进度（2026-08-22）：v1.4–v1.9 已完成本地实现与验证；v2.0 正在进行统一版本和最终验收。远端尚未推送。

## v1.4 — 可靠执行状态机

- 工具调用记录 `running`、`completed` 和 `uncertain` 状态。
- 执行记录包含租约到期时间；过期的运行态不会被静默当作成功。
- 已完成调用跨重启重放；不确定调用停止自动执行并要求人工处理。
- 保持高风险工具审批，不以恢复或重放绕过审批。

验收：覆盖完成态重放、活动租约冲突、过期租约转不确定、人工清除后重试。

## v1.5 — 可复现评测平台

- 增加工具参数准确率、错误类型、延迟预算和 Token 预算。
- 为工具使用、安全、RAG 和恢复建立离线测试集。
- 同一测试集按最近基线计算回归；门禁可由进程退出码接入 CI。
- 评测记录包含运行配置摘要，不保存提示词、模型输出或密钥。

验收：离线运行无需网络和 API Key；质量、成本或延迟超预算时门禁失败。

## v1.6 — 持久化可观测性

- HTTP Trace ID 贯穿聊天、LLM、工具和评测运行。
- Trace 摘要原子持久化并有数量上限，服务重启后可查询。
- 指标只使用固定名称，避免高基数和敏感参数泄漏。
- 提供 Trace 统计、错误和慢调用查询。

验收：跨重启读取 Trace；持久文件不包含提示词、工具参数或模型输出。

## v1.7 — E2E 与故障演练

- Playwright 覆盖启动、健康检查、会话生命周期和设置页。
- 增加检查点损坏、工具超时、评测回归和服务重启演练。
- 将无需外部模型的浏览器冒烟测试接入 CI。

验收：本地一条命令完成后端、前端和故障路径验证。

## v1.8 — 数据版本与迁移

- 为会话数据库、评测历史、Trace 和执行账本声明数据版本。
- 启动时拒绝未知的新版本，兼容读取受支持的旧版本。
- 提供原子备份、导出清单和恢复校验。

验收：旧格式可迁移、未知版本失败关闭、备份可在临时目录恢复。

## v1.9 — 发布候选门禁

- 增加安全配置检查、敏感信息扫描和性能预算。
- 固化 Python、前端、离线 Agent 和数据恢复发布命令。
- 生成机器可读的发布证据摘要。

验收：任何必需门禁失败时发布检查返回非零退出码。

## v2.0 — 稳定本地运行时

- 统一 Python、Web、启动器、文档和构建产物版本。
- README 能力表只保留经过测试证明的功能。
- 完成全量测试、前端构建、离线评测、迁移恢复和敏感信息检查。
- 明确边界：不宣称分布式 exactly-once、多租户 SaaS、高可用数据库或托管密钥服务。

验收：工作区干净；所有本地门禁通过；形成可回滚的 `v2.0.0` 本地提交检查点。

## 统一变更规则

1. 每阶段只修改一个行为路径，目标不超过 5 个文件和 200 行。
2. 每阶段先运行最小基线测试，再修改、复测并审查实际差异。
3. 数据格式变更必须有版本、兼容策略和恢复测试。
4. 不提交 `.env`、API Key、数据库、评测历史、Trace 或工具执行结果。
5. 远端推送、PR、合并和标签必须在本地全部完成后单独授权。
